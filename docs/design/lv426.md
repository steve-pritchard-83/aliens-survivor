# Second map: LV-426 colony (design)

## What exists

Navigation, pathing and spawning no longer depend on the Sulaco's constants. A map is described by a
`LevelDefinition` (`src/levels/LevelDefinition.ts`): hall rectangles with centre lines, junction positions and
adjacency, spawn nodes with fallbacks, player and companion start positions, and the motion-tracker outline.
`validateLevel()` checks a definition for mistakes, and `tests/levels.test.ts` proves the systems work on a second,
different layout (a straight hall). Registering a map is one data file plus an entry in `src/levels/index.ts`;
`setActiveLevel(id)` switches the map the systems read.

What is **not** data-driven yet is the 3D scene: `CorridorLevel` loads `corridor.glb`, trims and instances it into the
Sulaco's figure-8, and places lights and eggs by hand. A second map needs its own scene component.

## Proposed layout: "Hadley's Hope, Operations"

A compact colony block with a central atrium and three radiating service halls, so the player fights in the open
for the first time and retreats into corridors:

```
              N service hall (z 40..60)
                    |
   W hall ---- central atrium ---- E hall
   (x -30..-10)   (20 x 20 m)    (x 10..30)
                    |
              S service hall (spawn side)
```

| Element | Plan |
|---|---|
| Halls | 4 straight halls plus the atrium modelled as one wide hall (rect 20 x 20) with a centre lane per axis, so the existing lane-and-corner pathing still applies. Junction corners at each hall/atrium mouth |
| Pathing limits | Pathing is hall-based, so the atrium counts as one hall: aliens cross it in straight lines. Obstacles (consoles, crates) would need real nav (grid or navmesh): out of scope for the first version |
| Spawns | 10 to 14 nodes: wall vents in the service halls and ceiling ducts over the atrium; fallbacks on the far side from the start |
| Start | South hall end facing the atrium; companion 1.6 m behind |
| Waves | Same wave director and difficulty profiles; optionally a per-level override table (spawn interval or concurrency multipliers) |
| Tracker outline | Rectangles for each hall and the atrium |

## Work breakdown

1. `src/levels/lv426.ts`: the definition, validated by the existing tests (add it to `LEVELS`).
2. A scene component for the colony (geometry, baked lighting or emissive, the four-light cap respected: ADR 0001),
   with `registerEnvironmentRaycast` over its meshes and a BVH (ADR 0005).
3. Level selection: a menu choice (2D and VR) and `setActiveLevel` before `startGame`; persist a leaderboard per
   level and difficulty (`Leaderboard` keyed by level as well).
4. Budgets: any new GLB must be compressed (ADR 0004) and fit the precache limit (currently about 10.6 of 11 MB):
   raise the limit deliberately or lazy-load the second map's assets.
5. Tests: definition validation, pathing across the atrium, spawn visibility rules, an e2e that starts the map.

## Decision needed before building

The colony needs 3D assets (walls, atrium, props) that the project does not have, plus decisions on the visual scale,
art source and licensing (see `CREDITS.md`). **Owner decision:** supply or approve a model set (or accept a
simple primitives-and-materials look), and confirm whether a second map is wanted before further weapon work.
